# Public decisions

- Zero third-party dependencies: uses standard library only (`crypto/sha256`, `math`, `fmt`, etc.). `go.mod` has no `require` block.
- Root library package is `lmcode`, imported as `github.com/lmctl-ai/lmcode-go`.
- Strings are arbitrary byte sequences (including invalid UTF-8): kept as Go `string`, never ranged over as runes, never re-encoded or validated. Embedded NUL bytes are preserved.
- 64-bit two's-complement arithmetic with wraparound: the VM explicitly guards `math.MinInt64 / -1` (wraps to `math.MinInt64`) and `math.MinInt64 % -1` (evaluates to 0); native Go defines these same exceptional division results without a panic. Division and remainder by zero produce `RUN_ERROR`.
- Float formatting: `FormatG15` replicates C's `%.15g` exact behavior (`inf`, `-inf`, `nan`, `-0`) deterministically across platforms.
- Host objects: methods accept `self any` and arguments `args []Value`. The VM defensively checks the schema type name of `self` at call time.
- Host error reporting: callbacks return `(Value, error)`. Non-nil errors preserve existing `*Error` codes or wrap as `RUN_HOST`. Line and column reporting locates errors at the faulting bytecode instruction.
- Single test command: `go test ./...` runs 51 core conformance vectors, 61 optional catalog vectors, both vector-lock integrity checks, and native unit tests. Optional vectors use default std registries; legacy core fixtures opt out. Only trace/hex/sink fixture adapters require host callbacks. Native Go digest checks keep tests independent of shell discovery, including on Windows.
- Package `stdlib` provides all 16 functions in the C++ string catalog and the `RegisterString` binder. They are installed by the root default registry; the binder is a compatibility API and adds no VM opcodes or dependencies. `stdlib/string.schema-fragment.json` declares their exact signatures.
- Catalog offsets and lengths count bytes; substring slicing can split a UTF-8 codepoint. Case conversion changes only ASCII letters; trimming removes ASCII space and bytes 0x09 through 0x0d.
- Repeat and replacement preflight the 64 MiB result cap, including no-op replacement copies. Repeat rejects negative counts. Catalog resource policy failures are `RUN_HOST`, independent of VM resource policy.
- The built-in math catalog is ordinary callback code in the root package, forwarded by `stdlib/math.go`: integer abs/pow arithmetic wraps int64, integer `sqrt` is an exact floor root, negative integer pow/sqrt report `RUN_HOST`, and float min/max select the first argument on ties (including signed zero) while returning NaN when either input is NaN. Float pow preserves the specified `0` exponent, base `1`, and `+/-1` with infinite exponent special cases before native IEEE `math.Pow` behavior.
- Default collections use an SDK-owned 65536-object arena that is cleared at the start and end of each non-nested run; shared registry runs are rejected. Explicit `RegisterCollections` arenas remain manual and may be reset after prior handles expire. Testing output uses an explicit writer, with nil selecting stdout.
- The root `lmcode` package owns the canonical 69-signature standard surface. `NewRegistry()` enables it, `NewRegistryWithoutStd()` opts out, and `RegisterStd` is idempotent. Exact schema bytes are pinned in `std/lmcode-std.schema.json` and `std.lock`; `stdlib` remains a compatibility forwarding package.
- Decimal parsers accept complete signed tokens without whitespace or hexadecimal syntax. Integer overflow, nonfinite floats, and nonzero underflow to zero are invalid; conversion helpers return zero on failure. Representable subnormals and signed floating zero are preserved, without consulting process locale.
- Byte glob matching supports stars, question marks, negated classes, ranges and escapes, with constant auxiliary memory. Every matcher iteration, scanned class entry and skipped trailing star counts toward a 2^27 per-call work cap.
